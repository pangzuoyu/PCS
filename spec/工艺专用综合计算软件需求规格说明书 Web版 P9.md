第二部分：综合描述
2.1 产品前景
P9阶段将P1阶段构建的后端工作流引擎与前端UI整合，实现完整的四级电子签名工作流。这是系统从“计算工具”转变为“受控工程数据管理系统”的关键阶段。通过签署流程，确保所有设计成果经过规范的校核、审核、审定过程；通过变更影响分析前端，确保上游数据变更的透明性和可控性；通过ADMIN模块，确保系统的用户和权限管理规范有序。

2.5 设计和实现上的限制
状态机可配置且仅调用后端：记录层批准深度与交付物签署矩阵均由项目模板配置（V1.0"四级不可定制"作废）；前端仅调用后端API，不实现本地状态逻辑。

签署操作强制二次认证：各批准步骤与交付物签署通过时需二次认证（AD密码或MFA）；客户批准代录同样强制二次认证。

审计日志只读：前端不提供任何修改或删除审计日志的功能。

编辑锁时效：编辑锁有效期30分钟，可自动续期，前端需处理锁过期提示。

变更影响标识不可消除：在用户确认并重新计算前，橙色标识和锁定状态持续存在。

ADMIN用户管理不创建AD账号：仅同步和映射，实际账号管理在AD域控中完成。

3.2 功能需求
3.2.1 签署流程前端（V1.1：两层）
需求编号：P9-WF-001

功能描述：实现两层签署工作流的完整前端交互：记录层数据门禁（批准深度可配置）+ 交付物层签署矩阵（含客户代录与变更单）。

（1）可用操作判定——记录层

前端根据当前状态和用户角色，调用GET /records/{id}/actions获取可用操作（批准步骤角色由 record_approval_config 决定）：

当前状态	设计	各步批准角色	项目负责人
DRAFT	提交批准 / 弃用（未绑定）	—	弃用
IN_APPROVAL	—	当前步骤 通过/退回（显示 Step n/N）	—
CHECK_REJECTED	修改后重新提交	—	—
CHECKED（未绑定）	发起变更申请 / 弃用	—	弃用
CHECKED（锁定）	发起变更申请	—	—
STALE	确认重算（哈希判定）	—	—
CHANGE_PENDING	编辑 / 提交批准 / 放弃变更	当前步骤通过/退回	—
CHANGED	创建变更单 / 发起撤销	—	—
REVERSAL_PENDING	—	撤销批准链 批准/驳回	—
OBSOLETE	只读	只读	只读

（1b）可用操作判定——交付物层

交付物操作按签署矩阵当前步骤动态渲染（操作按钮/签署栏列数均由矩阵驱动，SUP-005）：

交付物状态	可用操作
DRAFT（未发布）	编辑绑定（仅可加 CHECKED 记录）/ 选版本目的并发布（生成 Rev）
签署中	矩阵当前步骤角色：通过/退回/批注；申请跳过（需审批）
CUSTOMER_PENDING	授权代录人（项目负责人/文控/审定）：代录批准 / 代录退回
APPROVED	只读；查看 Rev 时间线；AFFECTED 提示
变更单（CHANGE_NOTICE）	同上；APPROVED 后展示绑定记录 CHANGED→CHECKED 关闭结果
（2）提交操作

设计人点击“提交校核/审核/审定”按钮

系统检查输入完备性：若存在非VERIFIED的REQUIRED/CONDITIONAL输入项，弹出警告列出清单

用户可选择：①补齐后重新提交 ②继续提交但标记“含假设数据”

提交成功后状态更新，相关签署人收到待办通知

（3）通过/退回操作

签署人点击“通过”或“退回”按钮

通过时弹出二次认证对话框（AD密码或MFA）

退回时弹出意见填写对话框（必填）

通过时可选填写意见

操作完成后状态更新，设计人收到通知

（4）批注面板

需求项	规格
添加权限	所有签署角色均可添加
回复功能	支持线程式回复
关联状态	批注按状态关联，保留历史记录
只读场景	被锁定记录不可新增批注
（5）状态可视化

数据详情页顶部显示状态标签（颜色区分）；IN_APPROVAL 显示批准进度 Step n/N

提供状态时间线组件，展示流转历史（含 STALE/变更/撤销全程）

交付物签署页按矩阵动态列展示签署人信息（Rev / Description / Orig / Check / Review / Appr / Cust / Date）；客户栏显示"客户姓名（代录：X）"

（5b）代录客户批准（V1.1，ADR-0007）

签署矩阵走到 CUSTOMER 步骤 → 授权代录人（项目负责人/文控/审定，代录人不得为该交付物设计人）在弹窗中：上传凭证附件（必填，PDF/JPG/PNG/EML ≤20MB）+ 客户批准人姓名 + 批准日期 + 批准方式（邮件/信函/EDMS/签字文件）+ 代录人二次认证；审计记 CUSTOMER_APPROVAL_PROXIED。客户退回同样代录退回（退回原因必填），交付物回 DRAFT。

（5c）变更单审批（V1.1，ADR-0008）

变更单审批界面与交付物一致（复用矩阵/编号/Rev）；显示变更原因、change_type、绑定记录新旧哈希对比；APPROVED 后自动关闭绑定记录的 CHANGED 状态并通知设计人。

（5d）工作区按钮控制（V1.1，ADR-0004）

P9-WS-001 提交批准按钮在非 FORMAL 工作区禁用并提示
P9-WS-002 交付物/变更单创建按钮在非 FORMAL 工作区隐藏
P9-WS-003 个人区记录列表提供"导入正式项目"向导（提示将复制新记录从 DRAFT 重新走门禁、上游依赖记快照、原记录保留）
P9-WS-004 工作区切换时状态标签联动（个人/临时区恒显示"DRAFT（试算）"）

（5e）物流手动创建与出口物流校对（V1.2，ADR-0019/0022）

手动创建向导（三模式 CHEMICAL/PETROLEUM/SOLID）：炼油模式支持馏程/SARA/元素分析/金属录入与虚拟组分切割（手动或按 25°C 自动）；估算物性展示 estimated 标记清单供校对人核对

提交校对后进入与导入一致的校对流程 UI（校对项：来源一致性→手动场景改为"与化验报告/原始资料一致"（lab_report_ref）、组成归一化、单位、完整性、数值合理性）

设备计算完成自动创建出口物流（DEVICE_CALCULATED）后，通知中心向设计人推送"出口物流待校对"待办；物流链视图展示 {上游物流}--[设备]-->{本物流} 与各环节哈希状态

（6）待办列表

登录后首页展示待办事项

按项目、模块、优先级排序

支持批量处理（如批量校核通过）

点击待办跳转到对应记录详情页

（7）通知中心

顶部铃铛图标，未读数量角标

通知类型：签署任务、退回通知、变更报警、系统公告

支持标记已读、全部已读

通知保留策略：已读通知保留30天后自动清理

验收标准：

所有状态迁移在UI上正确展示

权限控制正确（越权操作按钮不可见或点击后403）

提交/通过/退回操作流程完整

二次认证生效

批注线程功能正常

待办和通知准确推送

3.2.2 变更影响分析前端
需求编号：P9-CIA-001

功能描述：实现上游数据变更后的前端展示和用户确认操作。

（1）受影响记录标识

需求项	规格
列表标识	受影响记录整行背景橙色（#FFA500），状态列红色感叹号
字段标识	受影响字段旁警告图标，悬浮提示“上游数据已变更”
置顶	受影响记录在列表和查询结果中置顶
详情横幅	详情页顶部显示“⚠ 上游数据已变更，当前结果可能失效”
（2）变更详情对比面板

展示新旧值对比（字段级）

展示影响范围（哪些下游记录受影响）

展示变更源信息（变更人、时间、原因）

提供“查看完整血缘”入口

（3）确认操作（V1.1：哈希判定路径）

操作	说明
确认并重新计算	使用最新上游数据重算 → 系统哈希判定：结果不变 → STALE 清除恢复 CHECKED（免凭证，审计 STALE_RESOLVED_NO_CHANGE）；结果变化 → CHANGE_PENDING 重新批准 → CHANGED → 凭证关闭（变更单/新版交付物）
放弃变更	CHANGE_PENDING 中设计人自行放弃，恢复变更前快照回 CHECKED
发起撤销	CHANGED 经 REVERSAL_PENDING 由撤销批准链批准后回滚
暂不处理	保持 STALE 只读与 AFFECTED 标识
（4）锁定状态提示

受影响记录在确认前为只读（STALE 状态本身承载只读，商务字段不受影响——设备记录）

显示锁定原因和解锁条件；绑定交付物 Rev 显示 AFFECTED 橙色标识

签署角色不可对 STALE/CHANGE_PENDING/CHANGED 记录执行批准操作；STALE/CHANGED 记录不可被新交付物绑定

验收标准：

受影响记录正确高亮

变更详情对比准确

确认并重算流程完整

手动调整记录理由

锁定和解锁逻辑正确
