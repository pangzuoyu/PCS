1. 增补说明
1.0 V1.1 作用域修订（SUP-007）

签署矩阵（Signature Matrix）驱动的是**交付物层状态机**。记录层不走签署矩阵——记录使用独立的可配置批准深度（record_approval_config，1~4 级步骤，SUP-007 §3.2/ADR-0012），字段为 approval_step/approval_depth/approval_role（无 matrix_id）。下文凡将签署矩阵作用于"数据记录/业务表"的表述，均应读作"交付物（deliverables）"。CUSTOMER 步骤经凭证代录闭环（SUP-007 §5.4/ADR-0007）。

1.1 增补目的
当前SPEC定义了固定的四级签署流程：设计（DESIGNER）→校核（CHECKER）→审核（REVIEWER）→审定（APPROVER）。但在实际工程实践中，不同文档类型和不同项目对校审层级的要求差异很大：

简单计算书可能只需设计+校核两级

设备数据表可能需要设计+校核+审核三级

正式发布文件可能需要设计+校核+审核+审定+客户批准五级

图纸类还需要额外的角色（Drawn/Draft Checker/Designed/Eng Checker）

小项目可能允许设计自校（Originator兼Checker）

特殊文档可能只需要Originator+Approver（如Void标记）

本增补将校审层级从固定状态机解耦为可配置的签署矩阵（Signature Matrix），由项目模板在CONFIG中定义。

1.2 核心变更概述
维度	原方案（固定四级）	新方案（可配置签署矩阵）

2. 签署矩阵模型
2.1 签署角色定义
2.1.1 系统内置签署角色
角色标识	名称	说明
ORIGINATOR	设计/编制	创建计算数据，提交校审
DRAFT_CHECKER	草稿校核	图纸类的第一级校核（Draft Check）
CHECKER	校核	对设计成果进行全面校核
DESIGNED	设计确认	图纸类的设计责任确认
ENG_CHECKER	工程校核	工程级别的校核（相当于审核）
REVIEWER	审核	对设计原则和方案进行审核
APPROVER	审定/批准	公司内部最终批准
CUSTOMER	客户批准	业主/客户批准
2.1.2 系统角色与工程签署角色的对应关系
系统用户角色	可担任的签署角色
DESIGNER	ORIGINATOR, DRAFT_CHECKER（如允许自校）
CHECKER	CHECKER, DRAFT_CHECKER, DESIGNED
REVIEWER	REVIEWER, ENG_CHECKER
APPROVER	APPROVER
SYSADMIN	不参与签署
项目负责人（新增）	可指定为任意签署角色（项目级临时指派）
2.1.3 自校规则（Originator=Checker）
配置项	说明
允许自校	设计可兼任校核（需审批）
自校条件	仅限小型项目或紧急任务
审计要求	兼任原因和审批记录必须留痕
限制	审核与审定不得由同一人兼任（任何情况下）
2.2 签署矩阵结构
2.2.1 定义
签署矩阵（Signature Matrix）定义某个文档类型/计算模块在某个版本目的下需要经过哪些签署步骤。

2.2.2 矩阵配置结构
json
{
  "matrix_name": "PIPE_CALCULATION_STANDARD",
  "module": "PIPE",
  "doc_type": "CALCULATION",
  "version_purpose": "ISSUED_FOR_DESIGN",
  "steps": [
    {
      "step_order": 1,
      "sign_role": "CHECKER",
      "step_name": "校核",
      "required": true,
      "can_self_check": false,
      "can_skip_with_approval": false,
      "action": "CHECK"
    },
    {
      "step_order": 2,
      "sign_role": "REVIEWER",
      "step_name": "审核",
      "required": true,
      "can_self_check": false,
      "can_skip_with_approval": true,
      "action": "REVIEW"
    },
    {
      "step_order": 3,
      "sign_role": "APPROVER",
      "step_name": "审定",
      "required": true,
      "can_self_check": false,
      "can_skip_with_approval": false,
      "action": "APPROVE"
    },
    {
      "step_order": 4,
      "sign_role": "CUSTOMER",
      "step_name": "客户批准",
      "required": true,
      "can_self_check": false,
      "can_skip_with_approval": true,
      "action": "CUSTOMER_APPROVE"
    }
  ]
}

参数	说明	可选值
步骤数	签署层级数	1~6
每步角色	签署角色	ORIGINATOR/CHECKER/REVIEWER/APPROVER/CUSTOMER等

是否允许跳过	有审批时可跳过	true/false

3. 修改后的状态机模型
3.1 动态状态机
原固定状态机（DRAFT→CHECKING→CHECK_PASSED→REVIEWING→REVIEW_PASSED→APPROVING→APPROVED）改为基于签署矩阵动态生成。

3.1.1 状态生成规则
给定签署矩阵的步骤数N，动态生成状态序列：

步骤数	状态序列
1级（仅Approver）	DRAFT→APPROVING→APPROVED
2级（Check+Approve）	DRAFT→CHECKING→CHECK_PASSED→APPROVING→APPROVED
3级（Check+Review+Approve）	DRAFT→CHECKING→CHECK_PASSED→REVIEWING→REVIEW_PASSED→APPROVING→APPROVED
4级（+Customer）	DRAFT→CHECKING→CHECK_PASSED→REVIEWING→REVIEW_PASSED→APPROVING→APPROVED→CUSTOMER_REVIEWING→APPROVED_CUSTOMER
6级（图纸）	DRAFT→DRAFT_CHECKING→DESIGNED_CONFIRMING→CHECKING→ENG_CHECKING→APPROVING→CUSTOMER_REVIEWING→APPROVED_CUSTOMER
3.1.2 通用状态命名规则
步骤角色	进行中状态	通过状态	退回状态
CHECKER	<DATA>_CHECKING	<DATA>_CHECK_PASSED	<DATA>_CHECK_REJECTED
REVIEWER	<DATA>_REVIEWING	<DATA>_REVIEW_PASSED	<DATA>_REVIEW_REJECTED
APPROVER	<DATA>_APPROVING	<DATA>_APPROVED	<DATA>_APPROVE_REJECTED
CUSTOMER	<DATA>_CUSTOMER_REVIEWING	<DATA>_CUSTOMER_APPROVED	<DATA>_CUSTOMER_REJECTED
DRAFT_CHECKER	<DATA>_DRAFT_CHECKING	<DATA>_DRAFT_CHECK_PASSED	<DATA>_DRAFT_CHECK_REJECTED
ENG_CHECKER	<DATA>_ENG_CHECKING	<DATA>_ENG_CHECK_PASSED	<DATA>_ENG_CHECK_REJECTED
3.1.3 兼容性
原四级签署状态机作为默认签署矩阵的结果继续有效。原状态枚举保留为：

原状态	对应签署矩阵中的位置
DRAFT	任何矩阵的初始状态
CHECKING	第1步=CHECKER进行中
CHECK_REJECTED	第1步=CHECKER退回
CHECK_PASSED	第1步=CHECKER通过
REVIEWING	第2步=REVIEWER进行中
REVIEW_REJECTED	第2步=REVIEWER退回
REVIEW_PASSED	第2步=REVIEWER通过
APPROVING	第3步=APPROVER进行中
APPROVED	最终状态（无Customer步骤时）
OBSOLETE	上游变更导致作废
3.2 上游变更回退规则（V1.1：整段替换，ADR-0003）
上游变更不再使交付物回退或作废重建。两层各自的路径：

对象	上游变更路径
未绑定的计算记录	直接回 DRAFT 重算
已绑定（锁定）的计算记录	→STALE（只读，存变更前快照）→确认重算→哈希不变恢复 CHECKED（免凭证）/哈希变化走 CHANGE_PENDING→CHANGED→凭证关闭
所涉交付物 Rev	标记 AFFECTED（快照与当前数据不一致）；实质变更经变更单或新版 Rev 关闭后，按 SUP-007 §3 恢复或保持 AFFECTED
无论签署矩阵如何配置，上游变更都不改变已发布交付物的历史 Rev。
