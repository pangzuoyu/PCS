## 验收基准的性质（关键）

基准由 `pcs-backend/scripts/p7_open_012_t5_r1_verification.py::_gb30251_reference()`
**独立重算**：不走 ORM / 不读 `ConfigEnergyConversionFactor` / 不调
`summarize_energy_year`。与被测路径**只共享两样东西**：

1. **输入量** —— 设备清单消耗量（kWh / Nm³ / t），工程数据，有效
2. **标准常数** —— GB 30251-2024 附录A 表A.1 原值，可对 PDF 逐行核验

因此该比对能检出**聚合、分类查表、舍入**类缺陷。

> **前车之鉴**：上一版基准（`1,242,159,527.8 MJ / 28,532.8967 t标油 /
> 40,761,279.4 kg标煤`）是**自证循环产物** —— 这三个数在原始 XLS 全表中根本不存在，
> 是 commit `6d74fdd` 时代代码输出的反抄（与旧输出仅差 10.8 MJ），
> 且 XLS 自身 `能耗!G33` 因 `D32=#VALUE!` 算不出年总能耗。
> 「输出 vs 自己旧输出」的比法检不出任何东西。

## 电折标口径政策（GB 30251-2024 §6.1.5）

用户裁决：「按 project 产品类型强制」。

- `Project.product_category` ∈ `{REFINING, ETHYLENE, OTHER}` + CHECK 约束
- `REFINING` / `ETHYLENE` ⇒ `EQUIVALENT_VALUE`（0.21 kg标油/kWh）
- 其余 ⇒ `EQUIVALENT`（0.086 kg标油/kWh）
- 省略参数 ⇒ 按产品类别推导；显式传值冲突 ⇒ **422 `ELECTRICITY_VALUE_TYPE_MISMATCH`**
  （fail-closed，承 F-P3-001 production 原则）
- 运维入口：`GET /projects/{project_id}`（含派生态 `electricity_value_type`）、
  `PATCH /projects/{project_id}/product-category`（SYSTEM_ADMIN；
  **已有综合能耗汇总时 422**，因为每条 summary 固化了当时的 value_type，改类别
  会让历史口径不可追溯）

## 封版范围与留白

**在封版范围内**：T5 综合能耗聚合 + 折标 + 容差验收 + 系数一致性 + 口径政策。

**刻意留白（不阻塞封版，登记 follow-up）**：

1. **T6 catalyst_loading fixture** —— BLOCKER-2 残余，工艺室 2026-10-15 XLS
2. **完整 Project CRUD** —— 本轮只做 `product_category` 可查可设；项目本体的
   创建 / 删除 / 列表仍靠外部导入或直改 DB
3. **`FUEL` 6 类（按吨计燃料）未接线** —— CONFIG 已有系数行，但当前
   `UtilityFuelGas` 是 Nm³ 口径、聚合按 `gas_source` 走，不会命中 `FUEL`。
   待「按质量计的燃料消耗」数据模型落地。**归 `FUEL` 而非 `FUEL_GAS` 是刻意的**
   —— 后者会被当 Nm³ 乘，`LPG` 1200 会算出 `Nm³ × 1200` 的荒谬值
4. **燃料气单位不可标准直校** —— 附录A 序号 8 以**吨**计（950 kg标油/t），
   PCS CONFIG 以 **Nm³** 计（0.85）。换算需气体密度假设，标准不直接可比。
   报告中标 `not_std_comparable: true`，沿用 R1 工艺室签署值
5. **`low_temp_heat_gj_yr` 恒为 0** —— P7-6B 的低温热子表未落地。
   系数已按标准就位（0.012），接上子表即生效
