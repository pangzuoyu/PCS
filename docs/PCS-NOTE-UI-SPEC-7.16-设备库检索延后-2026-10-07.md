## ⚠️ 下一版本启动前必须先解决的两个前提

### 1. `applicable_conditions` 是自由文本，区间查询无法在其上实现

`app/schemas/equip_lib.py` 的 `ApplicableConditions` 把工艺条件存成**字符串区间**：

```python
pressure_mpa: str | None   # "0.1~2.5 MPa"
temperature_c: str | None  # "-20~200 °C"
```

SPEC 要求的「参数区间」过滤需要数值比较，但库里存的是 `"0.1~2.5 MPa"` 这种文本 ——
**必须先决定数据模型**。可选路径（均未裁决）：

- 拆成数值列 `pressure_min` / `pressure_max`（干净，但改 settle schema + 存量数据迁移）
- 保留自由文本另加结构化列（兼容，但双份数据要防漂移）
- 查询时解析文本（不动 schema，但无法建索引，且解析失败需静默跳过）

**这是本项延后的真正原因，不是「工作量太大」。**

### 2. CATEGORY_6 在真库仍是 0 行

设备库功能从未被真实使用过。相似度与检索的全部能力目前**只在 SQLite 测试库中验证过**。
下一版本做前端页面前，建议先用真实沉淀数据跑一轮，确认相似度排序在真实数据上可用
（空库/合成数据下「≥90% 推荐」这类档位分布可能与实际不符）。
