# 加一个**筛选维度** ⇒ ⇒ ⇒ **所有读路径**都要跟着改

## 1. 现象：两个方向都堵死

P10-J · T2 加「打回」功能。人裁 ① = 「**退回 DRAFT + 一个『被退回』标记**」
⇒ ⇒ ⇒ **不新增 `REJECTED` 状态** ⇒ ⇒ ⇒ 9 态机一个字不改。

「被退回」由三个**列**表达（`rejected_at` / `rejected_by` / `reject_reason`）。

⚠️ 于是「被打回的草稿」= **`DRAFT` ∧ `rejected_at IS NOT NULL`**
⇒ ⇒ ⇒ **它有资格出现在任何 `status == 'DRAFT'` 的读路径里**
⇒ ⇒ ⇒ 而**读路径不止一条**：

| 读路径 | 该不该看到「被打回」的草稿 | 漏改的后果 |
|---|---|---|
| `pending_review()`（待审队列）| **不该**（它不是「待审」，是「待改」）| 队列里躺着「点了必失败」的行 |
| `update()`（改稿）| **要清标记** | 改完还显示「被退回」，且**永远不在队列里** ⇒ ⇒ **永远没人审** |
| `publish()`（发布）| **不该** | 「刚刚被自己打回的那一版」被**原样发出去** |
| `visible_clause()`（可见性）| **要**（创建人看得见）| — |

⇒ ⇒ ⇒ **四个读路径 ⇒ ⇒ ⇒ 改一个维度要改四处**
⇒ ⇒ ⇒ 漏一处 ⇒ ⇒ ⇒ **不报错、不炸、静默**。

## 2. 根因：**每个读路径各写一份 SQL**

`visible_clause` / `pending_review` / `update` / `publish` **各写各的谓词**
⇒ ⇒ ⇒ 「什么叫『待审』」这个概念**没有一个地方定义**
⇒ ⇒ ⇒ 加一个新维度 ⇒ ⇒ ⇒ **没有编译器提醒你「还有 N 处没改」**
⇒ ⇒ ⇒ 漏了 ⇒ ⇒ ⇒ 静默。

⚠️ **两个方向互相掩盖**是它最阴的地方：

- 只改队列、**不改** `update()` ⇒ ⇒ ⇒ 「打回信息没清干净」⇒ ⇒ ⇒ 像**小 bug**
- 只改 `update()`、**不改**队列 ⇒ ⇒ ⇒ 「没人提交」⇒ ⇒ ⇒ 像**业务问题**
- **都不改** ⇒ ⇒ ⇒ 「点了必失败」⇒ ⇒ ⇒ 像**前端 bug**

⇒ ⇒ ⇒ 谁也不会想到「**两处都要改**」⇒ ⇒ ⇒ 而正确解法恰恰是「改**两处**」。

## 3. 修法：把「态」的口径**收到一处**

① **一个标记 + 一处口径** —— 队列谓词直接写出来，并**紧挨着**写明它为什么不是
`status`：

```python
# ⚠️⚠️ **被打回的草稿不进队列**（P10-J · T2 · TODO-197b）
# ⇒ ⇒ ⇒ 「待审」（没被打回）与「待改」（被打回）是**两个态**
# ⇒ ⇒ ⇒ 审核者刚打完回 ⇒ ⇒ 它若还在队列里 ⇒ ⇒ 就是「点了必失败」
.where(ReportDefinition.rejected_at.is_(None))
```

② **闭环必须成对**：`update()` **清三个标记**
⇒ ⇒ ⇒ 创建人改稿 ⇒ ⇒ ⇒ 它**自动回到队列**
⇒ ⇒ ⇒ 「待审 / 待改」是**两个态**而不是**两个状态** ⇒ ⇒ ⇒ 不需要新状态。

③ **闸门补齐**：`publish()` 拒绝被打回的（409）
⇒ ⇒ ⇒ 「被打回」= **等创建人改** ⇒ ⇒ ⇒ 若此刻还能发布
⇒ ⇒ ⇒ 就是把**刚刚被自己打回的那一版**原样发出去。

④ **断言成对写**（**单测必须成对**）：

| 断言 | 断什么 |
|---|---|
| 打完回 ⇒ ⇒ **不在队列** | 队列口径 |
| 改稿 ⇒ ⇒ 标记**清了** **且重新在队列** | 闭环（**两个方向同时断**）|
| 被打回 ⇒ ⇒ 发布 **409** | 闸门 |

⇒ ⇒ ⇒ 「只改一处」⇒ ⇒ ⇒ **必红**。

## 4. 判别句（下次加「维度」先问这句）

> **这个新维度（列 / 标记 / 状态）出现在**哪些**读路径里？**
>
> ⇒ ⇒ ⇒ **列一遍**（列表 / 队列 / 详情 / 聚合 / 导出 / 搜索）
> ⇒ ⇒ ⇒ 每一处都要问：「**这一条该不该算它？**」
> ⇒ ⇒ ⇒ **漏掉的那一处**不会报错 ⇒ ⇒ ⇒ 它**只会**以
> 「数量不对 / 状态不对 / 点了失败」的面貌出现
> ⇒ ⇒ ⇒ ⇒ ⇒ ⇒ **看起来像别处的 bug**。

⚠️ **推论**：「加一个状态」比「加一个标记」**贵**，
因为状态机有**唯一的真相源**（`status`）⇒ ⇒ ⇒ 所有读路径都按它过滤
⇒ ⇒ ⇒ 而**标记**是**第三个维度** ⇒ ⇒ ⇒ 每个读路径都得**额外**判它
⇒ ⇒ ⇒ ⇒ ⇒ ⇒ **除非**你把「态」重新定义成**标记 + 状态**的组合
⇒ ⇒ ⇒ **并把组合口径收到一处**。
