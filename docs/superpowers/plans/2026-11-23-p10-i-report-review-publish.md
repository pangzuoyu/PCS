## T1 · TODO-197 · 「待我审核」队列 + 列表页发布按钮 ⚖️（**已裁决**）

### 问题的本质（不是「权限缺失」，是「流程在 UI 上走不完」）

| 环节 | 代码事实 | 结果 |
|---|---|---|
| 后端 `publish` | 角色闸 `PUBLISH_ROLES=(REVIEWER,APPROVER,SYSTEM_ADMIN)` + **禁自审 403** + **项目授权 404** | ✅ **权限模型是对的** |
| 前端入口 | 全仓**只有** `ReportDefinitionEditorPage` 的「保存并发布」⇒ ⇒ 且**只有创建人**能打开编辑器（`update()` 对非创建人 **404**）| ❌ 唯一入口 |
| 可见性 | `visible_clause`：**DRAFT 只有创建人可见**（`SYSTEM_ADMIN` 例外）⇒ ⇒ 审核者**看不见**可审的草稿 | ❌ 找不到东西 |
| 净结果 | 创建人 ⇒ **403 自审**；审核者 ⇒ **看不见**；**连 SYSTEM_ADMIN 都打不开**别人的草稿编辑器 ⇒ ⇒ **那个按钮对所有角色 100% 死** | ❌ SPEC §3.2.2 在 UI 上不成立 |

⇒ ⇒ 要修**必须同时**补两件：**(a) 审核者能「看见」可审的草稿**（只读）
· **(b) 一个不依赖编辑器的发布动作**。

### 裁决：选方案 ①（**待我审核」队列 + 列表页发布按钮**）

⇒ ⇒ **约束 1 · 队列是只读视图，不是「放开草稿可见性」**

- 审核者通过队列看到草稿的**元数据**（标题 · 创建人 · 项目 · 创建时间 · 摘要）
- **不能进入编辑器** ⇒ ⇒ `update()` 对非创建人 **404** 的现状**保持不变**
- 队列只提供两个动作：**发布 / 忽略**（「拒绝」本批不做 ⇒ T3）
- ⚠️ 这是 ① 与 ② 的**分界线**：能点进编辑器改内容 ⇒ ⇒ 就滑向 ② ⇒ ⇒
  那与「草稿只有创建人可见」的既有裁决**正面冲突**（半成品被审核者看到/改动 = 产品事故）

⇒ ⇒ **约束 2 · 队列的过滤条件与 `visible_clause` 分离**

| 草稿类型 | 审核者可见 | 条件 |
|---|---|---|
| 公司级（`project_id IS NULL`） | ✔ | `REVIEWER+` |
| 项目级（`project_id` 非空） | ✔ | `REVIEWER+` ∧ 我在该项目有 `user_projects` 授权 |
| 项目级 · 我无授权 | ✘ | ——（即使我是 `REVIEWER`）|
| `created_by == 我` | ✘ | ——（自审禁止 ⇒ 与 `publish()` 的 **403** 一致）|

⇒ ⇒ ⚠️ **这组规则必须写进队列端点的 docstring**（不是只写在实现里）
⇒ ⇒ 否则下一个维护者会以为队列 = 「所有 DRAFT」。

⇒ ⇒ **约束 3 · 「拒绝」本批不做** ⇒ ⇒ 登记 **TODO-197b** ⇒ ⇒ 归 **P10-J**

### 为什么不是 ② / ③ / ④（人裁的理由）

| 方案 | 否决理由 |
|---|---|
| ② 放开草稿可见性 | 与「草稿只有创建人可见」**正面冲突**；所有审核角色看见所有草稿（含半成品）⇒ ⇒ **产品事故面** |
| ③ 移交审核（指派） | 动数据模型 + 迁移 ⇒ ⇒ 风险大；且要求创建人**主动指派** ⇒ ⇒ 增加创建人负担；**创建人不指派 ⇒ 草稿永远卡死** ⇒ ⇒ 比 ① 更差 |
| ④ 按 id 发布 + 通知/待办 | 单靠它**解不了 UI 不可达**（前端入口仍需设计）；且「通知系统」是另一个大项 |

⇒ ⇒ ① 是最小可行的「**拉**模式」（审核者主动去队列看）⇒ ⇒ 未来可叠加 ③ 的「指派」
或 ④ 的「通知」变成「**推**模式」⇒ ⇒ 那是**增量**，不推翻 ①。

## T2 · TODO-187 · 两种 404 文案 ⇒ 存在性可枚举 ⚖️（**待裁决**）

### 范围（**已实测收窄** · 2026-11-23）

| 形状 | 调用点 | 有两种文案吗 |
|---|---|---|
| **project 级**（`/projects/{pid}/…` · 守卫是 404 的**唯一**来源）| **124 处** / 25 文件 | ❌ **已经同形**（不存在与无权都是 "Project not found"）|
| **record 级**（先按 id 取记录 ⇒ 再判授权）| **16 处** / 8 文件 | ✅ 有 |
| **混合**（端点自己抛「X not found」+ 再判授权）| 12 文件：checklist · cool_tower · cost_est · filtration · flare · flash · open_channel · psychro · report · supplier · util · workspaces | ✅ 有（每族 1~2 种文案）|

⇒ ⇒ **要改的只有 12 族**（不是「21+ 端点族」）⇒ ⇒ 工作量 ≈ **30~40 行**。

### 事实

- 守卫抛：`HTTPException(404, "Project not found: {project_id}")` ⇒ 信封
  `code="HTTP_404"` + `message=detail`（`app/core/errors.py:303-311`）
- 端点自己抛：`HTTPException(404, "<类型> not found")` ⇒ ⇒ **code 完全相同**
  ⇒ ⇒ **只有 `message` 能区分** ⇒ ⇒ 与本仓「无权 ≡ 不存在 ⇒ 逐字同形」冲突

### 三个选项（⚖️ **已裁决 2026-11-23 · 选 A**）

| | 做法 | 代价 | 效果 |
|---|---|---|---|
| **A（✅ 选中）** | 守卫加**可选参数** `not_found_code/message` ⇒ 12 族各传自己的「X not found」⇒ 端点自己的 404 与守卫的 404 **逐字同形** | 12 族各改 1~2 处调用 + 常量（≈ **30~40 行**）| 逐字同形 ✔ · **保留可诊断性** ✔ · 前端按 code 分流**不变** ✔ · **向后兼容** ✔（默认 = 现状）|
| **B（❌ 否决）** | 全仓统一成一句「资源不存在」（code 也统一）| 12 族 + **前端按 code 分流的盘点**（前端在用几十个专属 code）| 逐字同形 ✔ · 可诊断性**丢失** ✘ · 前端分流变粗 ⚠️ · **破坏性**变化 ✘ |
| **C** | 不改（接受现状）| —— | 需枚举 UUID + 消息不含数据内容 ⇒ ⇒ 但**规则持续分裂** ⇒ ⇒ 须明确登记「接受现状」 |

⚠️ **不能只改守卫那一侧**（把守卫改成 "X not found" 需要它知道资源类型 ⇒ ⇒ 它不知道
⇒ ⇒ 只能由端点传参 ⇒ ⇒ 也就是 A）。

⇒ ⇒ **落地条目 = TODO-187b**（`TODOS.md` · 含**两个约束**与**验收清单**）
⇒ ⇒ **严重度 🟢 low**（不是 medium）⇒ ⇒ **下一批做**（本批 T2 · 优先级低于 T1）。

**两个约束（人裁 · 必须写进实现）**

1. **同端点 · 同资源类型** ⇒ ⇒ 「不存在」与「无权」必须**逐字同形**；
   **不同资源类型之间可以不同**（"PsychroResult not found" 与
   "Project not found" 不同是正常的 ⇒ ⇒ 端点路径本身就暴露了资源类型）。
2. **守卫的默认文案 `"Project not found: {project_id}"` 不得因加参数而改变**
   ⇒ ⇒ **124 处 project 级**调用依赖它 ⇒ ⇒ ⚠️ **本条最大的回归风险点**
   ⇒ ⇒ **测试钉子**：至少一条断言 —— 不传 `not_found_message` 调用
   `check_project_access_or_404(...)` ⇒ ⇒ 仍抛 **`"Project not found: {project_id}"`**。

**落地清单（T2）**

- [ ] 守卫加**两个可选参数** `not_found_code` / `not_found_message` ⇒ ⇒ **默认 = 现状**
- [ ] ⚠️ **code 与 message 一起对齐**：端点自身的不存在若是 `PcsError(code=…)`
      ⇒ ⇒ 守卫也必须能覆盖 **code** ⇒ ⇒ **只传 message ⇒ ⇒ code 仍不同 ⇒ ⇒
      仍然可枚举 ⇒ ⇒ 没修掉**
- [ ] 12 族各 1~2 处调用点传自己的文案（**逐字**抄端点自身那条）
- [ ] 每族 **2 条参数化用例**：无权 ⇒ 与「不存在」**逐字相同**（code + message 都比）
- [ ] **约束 2 的钉子**单独一条
- [ ] **124 处 project 级零改动** ⇒ ⇒ 默认车道 + PG 车道跑一遍确认零回归
