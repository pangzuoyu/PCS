## 任务清单

### P10-J-T1 · TODO-177：公司级模板（`project_id IS NULL`）**不可执行** 🟡

**现状**：`execute_definition` 里 `scope = project_id or row.project_id`
⇒ ⇒ `project_id IS NULL` ⇒ ⇒ `scope is None` ⇒ ⇒ **400**
⇒ ⇒ 而端点传的是 `project_id=str(row.project_id or "")` ⇒ ⇒ **恒为空串**
⇒ ⇒ ⇒ 公司级模板**永远 400**（既有测试断的正是这个 ⇒ ⇒ **不是回归**）。

⚠️ **为什么「执行时指定项目」这条路走不通**：`ReportExecuteRequest`
**没有 `project_id` 字段** ⇒ ⇒ **没有任何入口能传项目 id**。

**要让它可执行需要**（**属新功能 ⇒ ⇒ 契约变化**）：
1. 给 `ReportExecuteRequest` 加 `project_id` ⇒ ⇒ 滚 OpenAPI baseline + 同步前端类型
2. 实现「指定的项目对执行者有授权」的判定（与 TODO-174 的 ③ 同款）

**待人裁**：
- ① 公司级模板该不该可执行？（还是说「公司级模板只做模板，执行时**必须**选项目」
  ⇒ ⇒ 那就把「执行时选项目」做成 UI 流程 ⇒ ⇒ 也需要 ①）
- ② 执行时选的项目若用户**无权** ⇒ ⇒ 404（与不存在同形）还是 403？

**验收**：
- [ ] 契约里 `ReportExecuteRequest` 有 `project_id`
- [ ] 「公司级模板 + 有权的项目」⇒ ⇒ 跑通（用例）
- [ ] 「公司级模板 + 无权的项目」⇒ ⇒ 404（用例）
- [ ] 前端「执行报表」有「选项目」入口

### P10-J-T2 · TODO-197b：「待我审核」队列需要**「拒绝」动作**（新状态 `REJECTED`）🟡

**来源**（2026-11-23 · 人裁 TODO-197 的**约束 3**）

⇒ ⇒ TODO-197 已裁走方案 ①（**P10-I · T1**）⇒ ⇒ 但那个队列**本批只做
「发布 / 忽略」** ⇒ ⇒ 审核者看到**不合格**的草稿 ⇒ ⇒ **没有「打回」的路**
⇒ ⇒ 产品上需要「拒绝」。

**为什么归本批而不是 P10-I**：「拒绝」要么**退回 DRAFT**（⇒ ⇒ 那不是拒绝，
是「退回修改」⇒ ⇒ 还要能通知创建人），要么**新增 `REJECTED` 状态**
⇒ ⇒ ⚠️ 新状态牵动**可见性 / 执行 / 列表过滤 / 前端 badge / 状态机**
⇒ ⇒ **那是新功能** ⇒ ⇒ 不是「收口批」该做的。

**待人裁**：
- ① 状态模型：**退回 DRAFT**（复用现有态 + 一个「被退回」标记）还是**新增 `REJECTED`**？
- ② 谁能看到 `REJECTED` 的定义？（创建人 / 项目内 / 审核者 / 不可见）
- ③ `REJECTED` 能不能**再编辑**（⇒ ⇒ 创建人要能改完再交审）？
- ④ 要不要**通知创建人**（⇒ ⇒ 牵动「通知系统」那一条）？

**验收**：
- [ ] 队列里能「打回」不合格的草稿 ⇒ ⇒ 创建人能看到自己被打回的草稿
- [ ] 打回后的状态 / 可见性 / 列表过滤 / 前端 badge 全部一致（无第二套规则）
