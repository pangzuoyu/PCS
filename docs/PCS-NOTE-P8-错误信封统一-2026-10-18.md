# PCS-NOTE：P8 错误信封统一为 PcsError（发布说明）

**日期**：2026-10-18
**范围**：`pcs-backend/app/api/v1/report.py`（报表与样式端点）
**来源**：ce-code-review `20261014-005528-981d772a` 的 P2 #17，用户 2026-10-14 裁决「统一为 PcsError，但需一次有意识的版本说明」——本文件即那次说明。

---

## 先修正评审的一个前提

评审 #17 说「同一路由混用两套错误信封，前端 `errorMessage()` 只读 `data.message`/`data.code`，于是『文件已被清理』『无权读取该样式』这类可操作文案永远到不了屏幕，用户只看到 `Request failed with status code 404`」。

**「文案到不了屏幕」不成立**（2026-10-18 实测）。

`app/core/errors.py` 注册了全局 `@app.exception_handler(StarletteHTTPException)`，
`HTTPException` 出站时**本来就被翻成同一个信封** `{code, message, detail, trace_id}`：

    GET /api/v1/report/verify/<uuid>?sig=deadbeef&exp=0
    → 403 {'code': 'HTTP_403', 'message': '签名已过期', 'detail': None, 'trace_id': '…'}

前端 `errorMessage()` 读 `data.message` 一直拿得到中文文案。

## 真正被修的是什么：**code 不语义**

`HTTPException` 站点的 code 是 `"HTTP_403"` / `"HTTP_404"` —— 把状态码复读一遍的占位符。
后果不是用户看不到文案，而是**机器侧无法区分不同的失败**：
「签名无效」与「签名过期」都是 `HTTP_403`、「文件不存在」与「文件已被清理」都是 `HTTP_404`。
前端想做「按 code 分支给不同提示」时，无从下手 —— 只能靠匹配中文 message。

## 契约变更（BREAKING，机器可见）

**变的是 `code`；`message` 与 HTTP status 均不变**，所以前端显示零变化。

| 端点 / 场景 | 旧 code | 新 code | status |
|---|---|---|---|
| `GET /report/verify/{id}` 密钥未配置 | `HTTP_403` | `REPORT_VERIFY_NOT_CONFIGURED` | 403 |
| `GET /report/verify/{id}` 签名过期 | `HTTP_403` | `REPORT_VERIFY_SIG_EXPIRED` | 403 |
| `GET /report/verify/{id}` 签名无效 | `HTTP_403` | `REPORT_VERIFY_SIG_INVALID` | 403 |
| `GET /report/{id}/download` 文件不存在 | `HTTP_404` | `REPORT_FILE_NOT_FOUND` | 404 |
| `GET /report/{id}/download` 文件已被清理 | `HTTP_404` | `REPORT_FILE_CLEANED` | 404 |
| `GET /report/{id}/status` 文件不存在 | `HTTP_404` | `REPORT_FILE_NOT_FOUND` | 404 |
| `GET /report/styles/{id}` 样式不存在 | `HTTP_404` | `REPORT_STYLE_NOT_FOUND` | 404 |
| `GET /report/styles/{id}` 无权读取 | `HTTP_403` | `REPORT_STYLE_FORBIDDEN` | 403 |
| `POST /report/styles` 等 权限被拒 | `HTTP_403/404` | `REPORT_STYLE_PERMISSION` | 不变 |
| `POST /report/styles` 等 作用域冲突 | `HTTP_409` | `REPORT_STYLE_CONFLICT` | 409 |
| `POST /report/styles` 等 竞态被唯一索引拦下 | `HTTP_409` | `REPORT_STYLE_CONFLICT` | 409 |

## 升级须知

- **前端**：无需改动。`errorMessage()` 优先读 `message`，且所有 `message` 未变。
  唯一行为变化是「同名 code 归一」——若将来前端按 code 分支，可用上表。
- **任何按 `code === "HTTP_404"` 分支的代码**（本仓内已 grep：无）需改用语义码。
- **MSW mock**（`pcs-frontend/src/mocks/`）不涉及这些端点，无影响。
- `detail` 与 `trace_id` 字段不变，`trace_id` 仍可用于日志关联。

## 顺带说明：为什么不用 `HTTPException`

`_style_call` 此前把 `StyleConflict` 翻成 `HTTPException(409, detail=str(e))`，
全局 handler 再翻回信封 —— **两跳**得到同一个结构。改为一跳：
service 抛 `PcsError` → 全局 handler 直接出信封。少一次翻译就少一处
「两套形状」的可能。

`report.py` 现在**没有任何 `HTTPException` raise**（grep 为 0）；
`_style_call` 的两条 `except` 分支同样改为 `PcsError`，
其中竞态分支仍只认 `uq_report_styles_one_active` 及其 SQLite 列名变体，
其余 `IntegrityError` 原样穿透（不被吞成 409）。
