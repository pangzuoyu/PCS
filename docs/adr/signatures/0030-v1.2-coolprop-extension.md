## 一、修订原因

V1.1（2026-09-16 accepted）基于 P5 范围（PSV / HEAT / VESSEL / SEP_EQUIP / PIPE / PIPE_NET / FLASH / PUMP）裁决 D3：CoolProp 清理 vendor 副本（无业务 import），不纳入 pyproject。

P6 SPEC V2.0（2026-09-19 评审委员会修订）新增 §3.2.5 PSYCHRO 模块，**业务实现依赖 CoolProp HumidAir**：

- `CoolProp.HumidAirProp.HAPropsSI` — 湿空气任意两参数求第三参数
- P6-2 PSYCHRO Task 26 落地 chedl_wrapper CoolProp 包装函数

D3 排除 CoolProp 的前提（"无业务 import"）已变化。本修订由 P6-0 架构负责人主导，**不属于决策 8 升级流程**（CVE / bugfix / 定期评估），而是 **SPEC 范围扩展触发的架构修订**。

## 四、与决策 8 的关系

决策 8 升级流程适用范围：

- CVE / 安全补丁 → P0
- PCS 已知 bug 修复 → P1
- 新需求依赖新版本功能 → P2
- 半年定期评估 → P3

V1.2 修订属于"P2 PCS 新需求依赖新版本功能"的子集：**PCS 新模块（PSYCHRO）依赖 ChEDL 生态外库 CoolProp**。但 CoolProp **此前未在锁定清单**，不存在"升级"语义，而是"首次引入"。处理上：

- 未来 CoolProp 升级：走决策 8 流程
- 本次首次引入：由 P6-0 架构修订处理（本签名归档）
