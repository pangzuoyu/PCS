## 四、评审意见

### 4.1 委员会肯定

1. **决策 11 的核心声明具有工程判断力**——"GB vs API 差异不是单位换算可以消除"，避免了用错误基准做验收的常见陷阱
2. **决策 8 的显式拦截设计**——先导式阀请求返回 422 + upgrade_hint，优于静默失败或隐式错误，与 G1/G2/G3 错误码风格统一
3. **决策 10b 的双重防护 + 可观测性**——service 层 + persist 层双重校验 + Prometheus 指标，工程成熟度高
4. **决策 11 分层阈值三表**——工艺室 + 标准负责人联签，将"由工艺室确认"落实为可执行数字，是 ADR 从"分析"到"决策"的关键跃迁
5. **V1.1 修订说明独立成段**——与 ADR-0030 模板对齐，评审委员会可快速定位修订内容
6. **决策 5 的"API 层前置校验 + DB CHECK 兜底"**——避免 IntegrityError 暴露为 500，用户可读性好

### 4.2 后续关注事项（非阻塞）

以下三项建议在 P5-3 实施阶段跟踪，但不影响本决议生效：

1. **决策 11 分层阈值的实测校准**——Task 13/14/16/17 实施时，如发现 ≤2% / ≤5% 阈值在特定工况下难以达成，需回评审委员会报备（不直接放宽，走增补评审）
2. **决策 7 的 two_phase_inherited_from 数据一致性**——Task 16 实施时需确保 GB 两相流记录的 `standard_profile_code="GB"` + `two_phase_inherited_from="API_520"` 双标注被 P6 FLARE_SYS 正确识别
3. **决策 8 的 upgrade_hint 文案**——Task 18 实施时可与工艺室沟通具体措辞（如升级流程、预计 P5+ 时间窗口），确保工艺室读取后可直接行动

### 4.3 实施约束

- Task 24 可在本决议生效后立即启动（P5-0-5 PSV 标准配置模型）
- Task 13/14/16/17 在 P5-0 批完成 + Task 24 落地后启动（P5-3 批）
- SUP-P5-PSV-001 §7 验收表同步修订由需求负责人依决策 11 落地路径第 1 条进行，与本决议联合生效
- V1.8 计划同步由计划负责人依"后续"段清单执行，同步完成后 V1.8 → V1.9
