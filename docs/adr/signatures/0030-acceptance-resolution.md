## 五、评审意见

### 5.1 委员会肯定

1. **V1.1 落地核验扎实**——pyproject:23/24/25 + uv run python -c "import" 双证据链，是 ADR 事实核验的范例
2. **决策 9 双包装层边界清晰**——明确"P4 冻结 vs P5 新增"，否决方案 Y（重构 P4）理由充分；P4 遗留调用清单 9 子模块完整记录
3. **决策 7 的"包装层内部允许 import"说明**——消除"fallback 示例违反决策 6"的潜在误读
4. **决策 8 的例外条款**——精确处理"uv 版本号回填 vs 决策内容不修改"的边界问题
5. **决策 8 的 4 类升级触发条件**——P0/P1/P2/P3 优先级清晰，含半年定期评估
6. **附录 B 的 ht 列加注**——"保留作为升级追踪位"精确处理"未锁定但未来可能引入"的中间状态
7. **D1-D4 ✔ 与 [ ] 语义分离**——"设计意图说明"段明确区分作者推荐与评审决议，是 ADR 元数据治理的优秀实践
8. **决策 5 的"化学品子模块核验粒度"说明**——明确"模块可导入即视为兼容"，避免过度核验
9. **决策 4 的"集合比较 vs 字节比较"替代方案**——精确识别 uv export 格式脆性问题

### 5.2 后续关注事项（非阻塞）

以下三项建议在 P5-0 实施阶段跟踪，但不影响本决议生效：

1. **决策 5 dir() 核验的首次执行**——Task 25 实施时，若发现 fluids.tanks 以外的非预期函数缺失，需立即报告评审委员会（可能影响决策 7 降级范围）
2. **决策 8 附录 C 的填充时机**——P5-0 批内无已知 bug 时标注"无"；P5-1 至 P5-4 实施中发现的 ChEDL 问题由各 task subagent 记录，P5 验收时汇总归档
3. **决策 4 uv 工具链版本号回填**——Task 25 实施时核验当前稳定版后，同步到 CI + Dockerfile + 决策 4 段；回填后视为"记录性更新"，不触发决策 8 升级流程

### 5.3 实施约束

- Task 25 (P5-0-6) 可在本决议生效后立即启动（ChEDL 版本锁定）
- Task 26 (P5-0-7) 依赖 Task 25（chedl_wrapper.py 创建依赖 ChEDL 版本锁定）
- Task 5/6/11（P5-1 / P5-2）在 Task 25 + 26 完成后启动（依赖 chedl_wrapper）
- V1.8 计划同步由计划负责人依"后续"段清单执行，同步完成后 V1.8 → V1.9
