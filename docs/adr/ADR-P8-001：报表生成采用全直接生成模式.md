ADR-P8-001：报表生成采用全直接生成模式
状态：已接受（Accepted）
日期：2026-10-07
决策者：首席架构师 / 工艺专家
替代：ADR-P8-001 初版（PDF 转换引擎选型：LibreOffice + unoserver 主路径 + pydocx-pdf 降级）
关联：ADR-P8-002（占位符 DSL）、ADR-P8-003（交付物写面延后 P9）、ADR-0028（HEAT 双 detail_level）

背景
P8 REPORT 引擎需要生成正式计算书、数据表、委托条件表，并输出 PDF（含二维码）。初始方案为"模板填充 + 格式转换"：

用户提供 .dotx / .xltx 模板

用 docxtpl / openpyxl 填充占位符

用 LibreOffice headless（unoserver）转换为 PDF

叠加二维码

该方案存在以下问题：

转换链路脆弱。LibreOffice 容器体积 ~500MB+，中文字体需额外安装，转换结果跨环境可能不一致，保真度约 95% 而非 100%。

模板约束强。.dotx / .xltx 模板结构固定，动态列、条件块、跨表合并等场景需在 Word/Excel 中预先设计复杂占位符，非开发者难以维护。

两条渲染路径并存。模板填充（正式文档）与直接生成（即席报表）需要两套代码，抽象层复杂，测试矩阵翻倍。

性能受转换引擎制约。LibreOffice 单文档转换 1–3s，冷启动 2–3s，异步队列易积压。

用户希望保留样式自定义能力，但自定义不应以"必须用 Word 设计模板"为唯一途径。

经评估，全部采用直接生成模式——即代码从零构建 DOCX / XLSX / PDF，不经过中间格式转换，也不依赖用户提供的二进制模板——能够消除上述全部问题，代价是样式需通过配置文件而非 Word/Excel 定义。样式自定义能力通过样式配置层（ReportStyle） 保留，用户提供的初始样式以配置形式落地。

决策
P8 报表生成全部采用直接生成模式，禁止使用模板填充 + 格式转换链路。

具体选型：

输出格式	主引擎	备选引擎	说明
DOCX	python-docx	—	成熟稳定，API 完整
XLSX	XlsxWriter	openpyxl（write_only）/ RustPy-XlsxWriter	功能最全，流式写入性能优
PDF	ReportLab	WeasyPrint	ReportLab 控制力最强；WeasyPrint 适合 HTML/CSS 模板化场景
同时废止：

LibreOffice headless / unoserver

pydocx-pdf / dxpdf / mtdxpdf / MiniPdf / Gotenberg / Aspose.Words FOSS

docxtpl（Jinja2 模板填充）

openpyxl 模板填充模式（仅保留 write_only 直接生成，或作为 XlsxWriter 的备选）

用户提供 .dotx / .xltx 模板文件的机制

样式自定义改由配置驱动，详见下节。

样式自定义机制（替代模板方案）
用户提供的初始报表样式不再以 .dotx / .xltx 文件形式存在，而是转化为样式配置文件（ReportStyle）。系统按样式配置直接生成 DOCX / XLSX / PDF。

用户如何提供初始样式
用户提供的初始报表样式通过样式配置包交付：

方式一（推荐）：用户提供一份带样式的 Word/Excel 样例文件，P8 开发期由开发者一次性转换为 ReportStyle JSON，纳入项目配置。

方式二：用户直接填写样式配置表（Excel 格式的字段清单），系统导入为 JSON。

方式三：P8 开发完成后，用户通过样式管理 UI（P8c 交付）在线调整样式，实时预览。

关键点：用户提供的样例文件仅作为样式提取来源，不作为运行时模板。运行时永远按 ReportStyle 直接生成。

样式配置的存储
表 report_styles：style_id / report_type / project_id（nullable）/ style_json / version / status

样式版本随报表生成记录冻结，保证可复现

样式变更走 CONFIG 审批流（复用 CATEGORY_4 机制）

选型理由
DOCX：python-docx
GitHub ~5.7K stars，MIT，社区最大，API 稳定

支持段落、表格、样式、页眉页脚、图片、分页符、节

性能：单文档生成约 11.8ms（基准测试），满足 ≤5s 预算

不依赖 Word，不依赖 LibreOffice，纯 Python

XLSX：XlsxWriter
功能最全：图表、条件格式、数据验证、公式、冻结窗格

constant_memory=True 流式写入，100 万行内存约 80MB

性能：100 万行写入约 23.84s，远优于 openpyxl 的 42.46s

性能升级路径：若后续成为瓶颈，可平滑迁移到 RustPy-XlsxWriter（~5.94s，快 ~8.7 倍）或 Jetxl（0.66s，快 ~36 倍）

PDF：ReportLab
控制力最强：Platypus 引擎支持内容在页间流动，适合数据驱动的长报表

表格能力成熟：Table + LongTable 对跨页表格支持完善

二维码可直接用 reportlab.graphics.barcode.qr 绘制，无需 pypdf 后处理

中文字体通过 pdfmetrics.registerFont(TTFont(...)) 注册，完全可控

零系统依赖，容器友好

性能：简单报表 <1s，复杂报表 1–3s，远优于 LibreOffice 转换的 1–3s（不含冷启动）

PDF 备选：WeasyPrint
HTML/CSS 驱动，样式与内容分离

适合用户希望用 HTML/CSS 自定义样式的场景

依赖 Pango/Cairo，容器需额外安装系统库

定位：作为 ReportLab 的备选，用于样式频繁变更、HTML/CSS 更合适的报表

被否决的方案
方案	否决原因
LibreOffice + unoserver	容器 500MB+，需中文字体包，转换 1–3s，跨环境保真度不稳定，冷启动开销
docxtpl 模板填充	依赖用户提供的 .dotx 模板，与"全直接生成"裁决冲突
openpyxl 模板填充	同上，且性能不如 XlsxWriter
pydocx-pdf / dxpdf / mtdxpdf / MiniPdf	保真度不足或成熟度不够，且在全直接生成模式下不再需要转换引擎
Gotenberg	需额外部署 Docker 容器，网络延迟，全直接生成模式下无必要
Aspose.Words FOSS	FOSS 版功能边界不明，社区小，长期维护风险
docx2pdf	本质是 LibreOffice 封装，无独立价值
python-docx 模板填充	python-docx 无 Jinja2 式模板机制，需手动实现占位符替换，不如直接生成
影响
正面
链路简化：单一渲染路径（代码 → 文档），无中间格式，无转换引擎。

保真度 100%：PDF 由 ReportLab 直接生成，不存在"转换后与 Word 不一致"问题。

容器精简：不再需要 LibreOffice，镜像体积从 ~500MB+ 降至 ~200MB（含中文字体）。

性能提升：PDF 生成 <1s（简单）至 3s（复杂），远优于 LibreOffice 转换链路。

中文字体可控：ReportLab 直接注册 TTF，不依赖系统字体包。

动态结构友好：列数、行数、条件块随数据变化，代码直接控制。

测试矩阵减半：只需测直接生成路径，不需要测"模板填充 + 转换"两段。

负面
用户无法用 Word/Excel 设计模板。样式自定义改为配置驱动，非开发者需要学习 ReportStyle 配置或使用样式管理 UI（P8c）。

样式提取需一次性工作。用户提供的 Word/Excel 样例需转换为 ReportStyle JSON，P8 开发期需完成此工作。

复杂排版需代码实现。页眉页脚、章节编号、目录、页码等需用 python-docx / ReportLab 手动实现，比 Word 模板设计更繁琐。

WeasyPrint 备选仍依赖系统库。若采用 WeasyPrint 路线，容器仍需 Pango/Cairo。

XlsxWriter 不支持读取。若未来需要"读取现有 Excel 修改"场景，需引入 openpyxl 作为补充（但与全直接生成裁决不冲突，因为那是"修改"而非"模板填充"）。

统一渲染接口
python
# app/services/report/renderer.py

class DocxRenderer(Protocol):
    def render(self, data: ReportData, style: ReportStyle) -> bytes: ...

class XlsxRenderer(Protocol):
    def render(self, data: ReportData, style: ReportStyle) -> bytes: ...

class PdfRenderer(Protocol):
    def render(self, data: ReportData, style: ReportStyle) -> bytes: ...


class PythonDocxRenderer:
    """DOCX 直接生成"""
    def render(self, data: ReportData, style: ReportStyle) -> bytes:
        doc = Document()
        _apply_page_style(doc, style)
        _render_header_footer(doc, data, style)
        _render_heading(doc, data.title, style)
        _render_tables(doc, data.tables, style)
        _render_assumptions(doc, data.assumptions, style)
        return _to_bytes(doc)


class XlsxWriterRenderer:
    """XLSX 直接生成"""
    def render(self, data: ReportData, style: ReportStyle) -> bytes:
        out = io.BytesIO()
        wb = xlsxwriter.Workbook(out, {"constant_memory": True, "in_memory": True})
        ws = wb.add_worksheet(data.sheet_name or "Sheet1")
        _apply_column_widths(ws, data.columns, style)
        _write_header(ws, data.columns, style)
        _write_rows(ws, data.rows, style)
        wb.close()
        return out.getvalue()


class ReportLabRenderer:
    """PDF 直接生成"""
    def render(self, data: ReportData, style: ReportStyle) -> bytes:
        out = io.BytesIO()
        doc = SimpleDocTemplate(out, pagesize=style.page_size)
        story = []
        story += _build_heading(data.title, style)
        story += _build_tables(data.tables, style)
        story += _build_assumptions(data.assumptions, style)
        story += _build_qr(data.qr_payload, style)
        doc.build(story, onFirstPage=_header_footer, onLaterPages=_header_footer)
        return out.getvalue()
二维码生成（ReportLab 直接绘制）
python
from reportlab.graphics.barcode import qr
from reportlab.graphics.shapes import Drawing
from reportlab.graphics import renderPDF

def _build_qr(payload: str, style: ReportStyle) -> list:
    qr_code = qr.QrCodeWidget(payload)
    bounds = qr_code.getBounds()
    width = bounds[2] - bounds[0]
    height = bounds[3] - bounds[1]
    size = style.qr_size_mm * mm
    d = Drawing(size, size, transform=[size/width, 0, 0, size/height, 0, 0])
    d.add(qr_code)
    return [d]
